# Dev Notes

A short log of problems, changes, and surprises while building Start Up.

## Layer 1

- Started with only index.html, style.css and game.js. The one task (Fix a Bug) is written directly in game.js for now; it moves to tasks.js in Layer 2.
- The task row is written straight into index.html for Layer 1 because there is only one. In Layer 2 the rows will be built with JavaScript so all five tasks come from tasks.js.
- The timer checks `Date.now() - startTime` every 100 ms instead of counting ticks, so it stays correct even if the browser slows the interval down.
- Tested by opening the page in a headless browser with a fake clock: click starts the bar, clicking again while running does nothing, and $10 is paid after 10 seconds.

## Layer 2

- Moved the task numbers into tasks.js (`taskList`) and the save code into save.js. The task row is no longer written in index.html; `buildTaskRows()` creates one row per task with `document.createElement`, so changing tasks.js changes the page.
- Problem: the level cost formula gave the wrong answer for Build a Feature. `100 * 1.15` is `114.99999999999999` in JavaScript because of floating point, so `Math.floor` gave $114 instead of $115. The same happens for Test a Release and Launch a Product at levels 1 and 2. Fixed by adding 0.001 before `Math.floor`. Checked that Fix a Bug still gives the examples from the plan: $17, $30, $60, $493, $16,254 for levels 1, 5, 10, 25, 50.
- The button click functions are made inside `makeWorkArea(i)` and `makeButtonArea(i)` instead of directly inside the `for` loop. With `var i` in a loop, every button would remember the last value of `i` (5), so every button would act on a task that doesn't exist. Passing `i` into a separate function gives each button its own copy.
- Each row is split into a clickable "work area" (character, name, bar) and a separate button area. If the whole row was clickable, clicking Level Up would also start the task.
- Design decision: locked rows still show the task name (greyed out) next to the Unlock button so the player knows what they are buying. The plan said "only an Unlock button"; I read that as "no Level Up/Hire buttons and no progress bar".
- At first the whole locked row was faded with `opacity`, which also faded the Unlock button so it looked greyed out even when the player could afford it. Changed it to fade only the left part of the row.
- `gameState` now has all the fields from the plan (money, totalEarned, tasksCompleted, tasks, achievements, investors, lastSaved), even the ones Layer 3 and 4 will use, so old saves don't need converting later. `fixMissingData()` still fills in anything missing from an older save, just in case.
- If the save text is broken and `JSON.parse` fails, the game starts a new game instead of crashing (try/catch in `loadGame()`).
- A task the player started by hand keeps its `startTime` in the save. If the page is reloaded while it's running, it simply finishes (or finishes right away if enough time passed) and pays once.
- The "Add $10,000 (testing)" button is in index.html inside a comment block marked TESTING ONLY. All of its code is in its `onclick`, so deleting that one block removes it completely. It only adds to money, not to totalEarned, so it doesn't count toward achievements.

## Layer 3

- Hiring: a hired task restarts by itself. If the tab was in the background, the game loop finds that more than one run has finished, so it pays `floor(secondsPassed / time)` runs at once and moves `startTime` forward by that many runs (not to "now"), so the leftover part of the current run is kept. Tested by jumping a fake clock forward 55 seconds with the Intern hired: it paid 5 runs ($50) in one tick.
- Speed milestones: the levels (10, 25, 50, 100) are a list in tasks.js so they can be tuned with the other numbers. Checked Fix a Bug: level 10 takes 5s and pays $100 (matches the plan), level 25 is 2.5s, level 50 is 1.25s, level 100 hits the 1 second minimum. Launch a Product only gets down to 18.75s at level 100 because 300 / 16 is still above 1.
- Times like 2.5 and 1.25 seconds show with decimals in the row ("$250 every 2.5s"). I left them like that because rounding them would show the wrong speed.
- If a level up passes a milestone while the task is running, the bar jumps forward because the same elapsed time is now a bigger part of a shorter run. I left this as is; it pays correctly.
- Sprites: to give the DevOps Engineer a headset without making a second sprite, the base sprite uses two extra letters. "A" is the top row of the head and "B" is the ear cup and microphone. For everyone else A is their hair color and B is "" (see-through), so the headset only shows for DevOps. I also gave two characters a different skin color, which wasn't in the plan.
- Each sprite is only redrawn when the character or animation frame changes (`lastSprite` in game.js) instead of 10 times a second for every row.
- Locked rows show the Founder, faded like the rest of the left side of the row.
- Messages: in Layer 2 the message box showed one message and the next one replaced it. With hiring added, "You hired the Intern!" is followed one tick later by the First Hire achievement message, so the first message would vanish almost right away. Changed `showMessage` to add a new line for each message and remove each line after 3 seconds.
- Offline progress: hired tasks earn `floor(secondsAway / taskTime)` runs, as planned. Changed one thing while writing it: at first I always restarted a hired task's timer at load time, but that means a quick reload throws away the current run (bad for Launch a Product at 300 seconds). Now the timer is only restarted if at least one run finished while away; otherwise the run just continues. Part of a run that was in progress when the game was saved is not counted when the player was away a long time, so offline earnings can be up to one run lower than "real" time would give. I kept the simple formula.
- Offline time is worked out from `lastSaved`, which is set when saving. Since the game saves when the page closes, this is close to the real time the player left.
- If the computer clock went backwards (time away is negative), offline time is treated as 0, and any task whose `startTime` is now in the future starts its run again, so the bar doesn't get stuck below 0%.
- The welcome back popup only shows if something was earned, so a quick reload with nothing finished doesn't show "you earned $0".
- Tested offline progress by changing `lastSaved` in the save by hand: 1 hour away with the Intern hired at level 10 (5s, $100) plus a Build a Feature run started by hand gave $72,075 = 720 runs x $100 + one $75 run. 20 hours away gave exactly 8 hours' worth ($576,000) and said it hit the 8 hour limit. A save from 1 hour "in the future" gave $0 and no popup.
- Achievements are kept in `gameState.achievements` as `{ firstPaycheck: true, ... }`. They're checked every tick in `checkAchievements()`. First Paycheck uses `tasksCompleted >= 1`.

## Bug fix: tasks never finish (before Layer 4)

- Problem reported after copying the code into VS Code: clicking a task changed the row, but the bar never filled and nothing paid. Buttons, Stats, Save and Reset still worked. The code on GitHub worked in my tests, so I looked for what could break it in a copied folder. I got the exact same symptoms when `sprites.js` didn't load (renamed or missing). Cause: `startGame()` called `updateScreen()` before `setInterval(gameTick, 100)`. `updateScreen()` calls `drawSprite()` from sprites.js, so when that file was missing it crashed, `startGame()` stopped, and the tick timer was never started. Clicking still worked because `clickTask()` sets `running` and `startTime` itself; the only sign was an error in the console.
- Fix: `checkFilesLoaded()` checks that tasks.js, sprites.js and save.js loaded, and if not, it shows a red message on the page naming the missing file instead of failing silently. The timers now start before the first `updateScreen()`.
- Also made loading safer: `fixTaskData()` repairs each task from the save (level not a number, missing true/false values, a running task with no `startTime`), and money that isn't a number goes back to 0. Tested with a save that had a running task with no start time: it starts that run over and pays after 10 seconds.
- Added temporary `console.log` lines starting with "DEBUG" (start of game, click, once a second while running, payout) to check the loop in the browser console. These will be removed once the fix is confirmed.

## Layer 4

- Pivot: added `runEarned` to `gameState`. `earnMoney()` adds to it, so offline earnings count too. Pivoting replaces `gameState.tasks` with a fresh list from `makeNewGame()` and sets money and runEarned to 0. Investors, achievements, totalEarned, tasksCompleted and the sound setting are kept. Old saves without `runEarned` get 0 from `fixMissingData()`, so nobody can pivot right away from earlier play.
- The bonus is `1 + 0.1 * investors`, and the Investor Meeting doubles it. Floating point caused trouble again: `0.1 * 3` is `0.30000000000000004`, and some products like this can land just under a whole number, so I used the same `+ 0.001` before `Math.floor` as in the level cost. Checked Fix a Bug at level 7 with 0 to 12 investors: $70, $77, $84 ... $154, all exact.
- Pivot asks for confirmation first because it resets a lot of progress.
- Random events: the first event comes 60 to 120 seconds after the page opens, then each next one 60 to 120 seconds after the last one started. Each event lasts 15 seconds at most, so two can't overlap. Event state isn't saved, so reloading the page ends an event or a x2 boost. That kept save.js simpler.
- Server Outage: the plan said tasks pause for 10 seconds "unless the player clicks Fix It first". I made the outage start right away and pause everything, and Fix It ends it early. I couldn't see how else the player would know about it before it happened.
- Pausing was harder than expected because all timers use `Date.now() - startTime`, so time keeps passing during the outage. Fix: while the outage is on, `checkTask()` does nothing and the progress bars are drawn using the time the outage started. When it ends, every running task's `startTime` is moved forward by the length of the outage, so its bar continues from where it stopped. Hiring during an outage no longer starts the task right away. `checkTask()` starts hired tasks once the outage is over; otherwise their start time would be pushed back too far.
- Events only start while the tab is visible (`document.hidden`). Otherwise a meeting could come and go while the player is in another tab.
- Sound works in this style with the browser's built-in Web Audio API: `new AudioContext()`, an oscillator (the beep) and a gain node (the volume). There are no sound files. Three beeps: high and short for a payout, middle for a purchase, low and long for an event. The on/off setting is saved in `gameState.soundOn`. If the browser has no AudioContext, the game just stays silent. Browsers block sound until the player has clicked something on the page, so the first beep you hear comes after your first click.
- With several characters on 1-second tasks, the payout beep plays very often. That's what the Sound button is for.
- Added two more buttons in the TESTING ONLY block: "Earn $1,000,000 (testing)", which counts toward runEarned so you can test Pivot, and "Start random event now (testing)".

## Layer 5: click fix, faster levels, team, outages, hacker breach

- Click bug ("sometimes a click does nothing"): the rows were NOT being rebuilt every tick. They are made once in `buildTaskRows()`, and the click functions are attached once. I tested it in a browser by pressing the mouse at different spots on a button. The real cause was the CSS `button:active { transform: translate(3px, 3px); }`, which moves a pressed button 3px down and right. If you press near the top or left edge, the button slides out from under the mouse, so the mouse is released over the area behind it and the browser never sends the click to the button. Spam clicking makes it worse because you're more likely to hit an edge. Fix: pressed buttons now only lose their shadow and don't move.
- Also changed `updateScreen()` so it only writes to the page when something actually changed (`setText`, `setClass`, `setShown`, `setDisabled`, `setBarWidth`). Before, it rewrote the text of every row 10 times a second even when nothing changed. That wasn't the cause I could reproduce, but it is wasteful and can interfere with clicks in some browsers. Added `user-select: none` to the clickable part of the task rows so fast clicking doesn't highlight the text.
- Checked the other guesses too: `saveGame()` only reads `gameState` (it never changes it except `lastSaved`), `loadGame()` only runs once at the start, and `running` only changes when a run starts or finishes, so none of those were the problem.
- 4% shorter every 5 levels: `time = max(1, baseTime * 0.5^halvings * 0.96^floor(level / 5))`. The 0.96 is `fiveLevelSpeedUp` in tasks.js. The times aren't round numbers any more (4.608 seconds), so `formatSeconds()` rounds them to 2 decimals for the screen only; the game itself uses the exact time. Checked: level 5 = 9.6s, level 10 = 4.61s, level 25 = 2.04s.
- Team: stored as `gameState.team`, a list of `{ hired, level }`, number 0 is IT Support and number 1 is Cybersecurity. The numbers (costs, max level) are in `teamList` in tasks.js. Old saves without a team get one from `fixMissingData()`.
- I decided Pivot also resets the team, because they are hires and the Pivot rule says hires reset. Losing to a hacker resets them too, as the plan said. Both use the same `startOverRun()` function now, so they can't drift apart.
- The Cybersecurity sprite needed green details on a black hoodie, so the base sprite got a new letter "G" (hoodie strings). For every other character G is just their shirt color. The hacker uses the same desk sprite with a dark hood, dark face and green eyes.
- Outage: removed the Fix It button. The length is `max(3, 30 * 0.85^itLevel)`, or 30 seconds without IT Support. The length is worked out when the outage starts, so leveling IT during an outage doesn't shorten the one that's already going. The pause still works by moving every running task's `startTime` forward by the outage length when it ends.
- Hiring a character during an outage doesn't start their task until the outage is over (`checkTask()` does nothing during an outage).
- Event chances: once breaches are possible, 20% breach, 40% outage, 40% meeting. Before $100,000 earned it's 60% outage, 40% meeting, and before $5,000 only meetings. No new event starts while a breach is going on.
- Hacker breach: `gameState.breachActive` is saved the moment the breach starts (`saveGame()` right away), so closing or refreshing the page can't be used to escape. When the game loads and finds it still true, it shows the "infiltrated" popup straight away and skips the offline money. The flag only goes back to false when the player wins or clicks Start Over, so refreshing on the "infiltrated" popup doesn't escape either.
- The breach timer, problems left and answer are not saved (they don't need to be, because reloading is a loss anyway).
- Losing also resets `runEarned` (money earned since the last pivot), since it is part of the run that was lost. Investors, achievements, totalEarned and tasksCompleted are kept.
- Math problems: subtraction picks the smaller number below the bigger one so the answer is positive, and division picks the answer first and multiplies, so it always comes out even. Tested 2,000 random problems: all whole numbers and all answers matched. The answer box uses `parseInt`, and an empty box says "Type a number first." instead of counting as wrong.
- Payout is now `basePayout * level * (1 + 0.1 * investors) * eventBonus`, where eventBonus is x2 (meeting) times x1.5 (security) when they are active. Checked: level 1 Fix a Bug with both boosts pays $30.
- The breach popup has to keep the text box working while the screen updates 10 times a second. Because of the new `setText` helpers, the popup only changes the timer text and bar each tick, and never touches what the player is typing.
